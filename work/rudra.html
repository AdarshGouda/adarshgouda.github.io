RUDRA autonomous rover

A self-directed build that grew from a first mobile prototype into a modular ROS platform for mapping, planning and autonomous navigation.

Three generationsROS · C++ · PythonEmbedded + electromechanical
01 Problem02 Approach03 System04 Decisions05 Result06 Lessons

Problem

Build an autonomous mobile robot that could map an unfamiliar indoor environment, localize itself, plan a route and navigate it, while remaining inexpensive and adaptable. The deeper objective was systems learning: make mechanics, power, embedded firmware, computation, sensors and autonomy behave as one machine.

Approach

I developed RUDRA iteratively. Each generation had a bounded learning purpose: establish motion and ROS control, improve the platform and sensing architecture, then consolidate the design around a cleaner compute and LiDAR stack.

  • Prototype the complete loop early, from velocity command to wheel motion and odometry.
  • Keep the mechanical, power and compute layers replaceable so that one experiment did not freeze the architecture.
  • Use real navigation behavior, not isolated component demonstrations, as the integration test.

System

The rover combines a differential-drive base, embedded motor control, wheel feedback, a ROS host, range sensing and a navigation stack. Hardware evolved across Arduino and Teensy control, Jetson Nano and Intel NUC compute, and RPLiDAR and YDLiDAR sensing.

Engineering Decisions

Modular over monolithic

Separate the robot base, embedded controller and ROS computer so each layer could be replaced without rebuilding the whole platform.

Differential drive

Favor mechanical simplicity and mature kinematics, accepting the need to manage slip and odometry error.

Incremental autonomy

Validate teleoperation and motor control before adding SLAM and navigation, keeping faults observable.

Budget as a constraint

Use accessible components and deliberate interfaces rather than solving uncertainty by buying a finished robot.

Result

RUDRA matured into a working autonomous-navigation platform and a repeatable environment for learning ROS integration. The project demonstrated manual and autonomous control, mapping, localization, path planning and navigation across successive hardware configurations.

Lessons Learned

  • Autonomy failures often begin as ordinary interface failures: power integrity, timing, frames, wheel geometry or sensor placement.
  • A modular architecture accelerates learning only when interfaces are explicit and observable.
  • Simulation is useful, but a physical robot reveals interactions that component-level models hide.
  • Repeated end-to-end tests create better engineering judgment than perfecting one subsystem in isolation.
